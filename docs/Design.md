# Внутренние требования и дизайн

## 1. Функциональные требования

| ID | Требование | Где реализовано | Проверка |
|---|---|---|---|
| F1 | Квадратный корень из комплексного числа (главная ветвь) | `Complex.sqrt` | `test_complex_number.py`, `test_blackbox_api.py` |
| F2 | Длинные числа, заданная точность 1–1000 значащих цифр (GUI и API одинаково) | `api.evaluate`, `decimal` | граничные тесты 1 / 28 / 100 / 1000 |
| F3 | Выражения: `+ - * / ^`, скобки, `i`, функции `sqrt abs conj re im`, переменные | `parser.py` | `test_parser.py` |
| F4 | Аналитическое упрощение с переменными (`sqrt(x^2) → abs(x)`) | `simplify.py` | `test_simplify.py` |
| F5 | Точная форма для рациональных подкоренных выражений (`√8 → 2√2`, `√(1/2) → √2/2`) | `exact.py` | `test_exact.py` |
| F6 | GUI с управлением точностью вывода | `ui/app.py` | `test_blackbox_gui_logic.py` + ручной смоук |
| F7 | Интерфейс на ru, en, es, zh (+ ja) с переключением на лету | `ui/i18n.py` | `test_i18n.py` |
| F8 | Проверка обновлений по запросу | `updates.py` | `test_updates.py` |

## 2. Нефункциональные требования

| ID | Требование |
|---|---|
| N1 | **Отказоустойчивость:** любой ввод даёт результат или локализованную ошибку не более чем за 5 с; приложение не падает. |
| N2 | **Переносимость:** один файл, без установки, без прав администратора, без Python у пользователя. |
| N3 | **Без следов:** никаких настроек, реестра, AppData, логов; удаление = удаление файла. |
| N4 | **Без сети по умолчанию:** сеть только по явной команде «Проверить обновления». |
| N5 | **Без сторонних зависимостей в рантайме:** только стандартная библиотека Python. |
| N6 | **Покрытие тестами** ветвей пакета `squareroot` не ниже 95% (проверяется в CI). |
| N7 | **Платформы:** Windows 10/11 x64, macOS 13+ (arm64, x86-64), Linux x86-64 с glibc 2.39+. |

## 3. Дизайн интерфейса

Одно окно, сверху вниз в порядке действий пользователя:

```
┌ Файл  Правка  Язык  Справка ───────────────────────────┐
│ ВЫРАЖЕНИЕ (ПОД КОРНЕМ)                                  │
│ [√] [ 8                                              ]  │
│ ТОЧНОСТЬ                                                │
│ [ 40 ⇅]   [ Извлечь корень ]                            │
│ ПЕРЕМЕННЫЕ  подставляются в упрощённый результат        │
│ ┌ имя ─────┬ значение ──────────┬ × ┐                    │
│ └──────────┴────────────────────┴───┘  [+]              │
│ ┃ √(8) =                                                │
│ ┃ 2.828427124746190097603377448419396157139             │
│ ┃ точно: 2√2                                            │
├─────────────────────────────────────────────────────────┤
│ OK                           decimal · точность 40      │
└─────────────────────────────────────────────────────────┘
```

Правила:

- **Цвет полосы результата кодирует состояние:** бирюзовый `#0f766e` —
  число, оливковый `#7c8a38` — символьный результат, красный `#a5382f` —
  ошибка, серый — ожидание. Состояние дублируется текстом в строке статуса
  (цвет не единственный носитель смысла).
- **Шрифты:** системные (`TkDefaultFont`, `TkFixedFont`), числа — моноширинным,
  результат крупнее на 8 pt. Системные шрифты дают кириллицу, CJK и
  одинаковый вид на всех ОС без встраивания шрифтов.
- **Длинные числа** переносятся по ширине окна (до 1000 цифр), окно не растёт.
- **Тема ttk** `clam` (есть на всех ОС), минимальный размер окна 560×620.
- **Тексты** только через `i18n.translate`; строк в коде виджетов нет.
  Заголовки секций — заглавными, кнопки — глаголом («Извлечь корень»).
- **Ошибки** показываются в панели результата (тип + понятное сообщение),
  а не во всплывающих окнах; всплывающие окна — только для точности вне
  диапазона, «О программе» и обновлений.
- Язык по умолчанию — из локали ОС, иначе русский.

## 4. Правила разработки

- Python 3.9+, стиль PEP 8, длина строки до 100.
- Ядро (`squareroot/*`) не импортирует `tkinter`; `ui/logic.py` и
  `ui/i18n.py` тоже — они тестируются без дисплея.
- `float` в ядре запрещён (только `Decimal`/`Fraction`/`int`).
- Каждая пользовательская ошибка — подкласс `SquareRootError` с `code`;
  новый код обязательно получает перевод на все языки (тест это проверяет).
- Рекурсия ограничена явно (`MAX_NESTING`, `MAX_TREE_DEPTH`).
- Ветки: `main` защищена, работа в `feature/*`, слияние через PR с одним
  ревью и зелёным CI.
- Коммиты — повелительное наклонение, одно логическое изменение на коммит.
- Версии — SemVer, единственный источник — `squareroot/__init__.py:__version__`.

## 5. Стратегия минимальной поддержки (пункт 9)

Основной приём — **программа без состояния и без установки**. Самый дорогой
вид поддержки у настольных программ — не ошибки в коде, а окружение:
установщики, права, остатки старых версий, повреждённые настройки,
конфликты зависимостей, «у меня не удаляется». Здесь всё это исключено
конструктивно:

| Источник обращений в поддержку | Как устранён |
|---|---|
| Установка/права администратора | установки нет, один файл |
| Зависимости, версии Python, DLL | всё внутри бинарника, в рантайме только stdlib |
| Повреждённые/старые настройки | настроек нет, язык из ОС |
| Конфликт версий при обновлении | обновление = заменить файл, поддерживается только последняя версия |
| Неполное удаление | удалять нечего, кроме файла; скрипты для аварийных остатков |
| «Программа упала» | любое исключение превращается в локализованное сообщение |
| Сборка под разные ОС вручную | CI собирает и проверяет всё по тегу `v*`, человек только ставит тег |
| Непонятные ошибки | каждое сообщение переведено и объясняет, что не так с вводом |

В итоге регламентная поддержка — около 5 часов в месяц (см.
`ProjectManagement.md`, раздел 5), в основном обновление CI-окружения.
